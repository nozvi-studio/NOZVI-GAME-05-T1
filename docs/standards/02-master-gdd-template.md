# 02 — Master GDD Template

> **Master GDD** — concise design overview and index of detailed specs. Do not duplicate authoritative mechanic rules.
> For casual-game repos the concrete file layout is `templates/GDD.md` (used for `docs/GDD.md`); this page lists the topics a master GDD must cover.

## Metadata
ID: GDD · Owner: Game Designer · Status: Draft · Version: 0.1

## 1. Game overview
One-line pitch, player promise, audience, platform and reference links (Game Brief).

## 2. Game pillars
2–3 principles; each includes a concrete consequence for design choices.

## 3. Core gameplay
Player objective, core verbs, moment-to-moment actions, reward and challenge loop. Include a short flow diagram when helpful.

## 4. Mechanics index
| ID | Mechanic | Player-facing purpose | Spec | Status |
| --- | --- | --- | --- | --- |
| MEC-001 | [Name] | [Why it exists] | [Link] | Draft |

## 5. Session & game flow
Boot, start, play, pause, win/lose, retry, background/resume. Expected run and sitting lengths as testable targets.

## 6. Difficulty & progression
Difficulty dimensions, new mechanic introduction, level/endless structure, balance spec links.

## 7. Player experience
Controls, onboarding, feedback, UI readability, accessibility and UX flow links.

## 8. Art & audio direction
Visual identity, legibility, sound and haptics; links to asset production specs.

## 9. Retention & monetization
Replay motivations, optional meta, ad/IAP principles and fairness; link to placement and economy specs if used.

## 10. Scope & validation
MVP vs later, milestones, hypotheses, playtest goals and acceptance gates.

## Dependencies and open questions
Design dependencies, unresolved decisions, risks, linked project documents.

## Exclusions
Do not put class diagrams, SDK credentials, giant balance tables or CI/CD instructions here.
